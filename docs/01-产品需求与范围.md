# 01 · 产品需求与范围

> 定位：定义做什么、不做什么、做到什么程度算完成
> 状态：v1.0 · 已评审

---

## 1. 用户画像

| 画像 | 诉求 | 本项目是否服务 |
|:---|:---|:---|
| 开发者（本人） | 练手 Python 后端 + 分布式基础 | ✅ 主要服务对象 |
| 演示受众 | 看到"能跑的 IM" | ✅ 次要 |
| 真实聊天用户 | 长期稳定的聊天工具 | ⚠️ 不做生产级保障 |

**本项目的第一用户是开发者本人**，不是终端用户。
所有需求优先级以此为准：能练到技术 > 功能完整 > 体验精美。

## 2. 核心场景

```
注册/登录 → 进入会话列表 → 发起单聊/群聊
  → 发送文本消息 → WebSocket 实时推送到对方
  → 向上滚动加载历史（游标分页）
  → 消息已读回执、点赞、回复
  → 与 AI 机器人对话（M8）
```

## 3. 功能范围（MoSCoW）

### Must have（不做则项目失败）

| 功能 | 里程碑 | 验收要点 |
|:---|:---:|:---|
| 注册 / 登录 / JWT 认证 | M1 | 密码 bcrypt 哈希；错误码统一 |
| 单聊会话 + 文本消息 | M2 | 首次发起自动建 room，重复发起复用 |
| WebSocket 实时推送 | M3 | 握手认证、心跳、断线重连补发 |
| 历史消息（游标分页） | M2 | 禁止 offset；翻页不重不漏 |
| 群聊（建群/加人/退群） | M4 | 非成员无法读写该群消息 |
| 敏感词过滤 | M7 | 命中替换为 `***` |
| 接口频控 | M7 | 发消息 20 条/分钟 |

### Should have（重要但可延后）

| 功能 | 里程碑 |
|:---|:---:|
| 好友关系（申请/通过/删除）、黑名单 | M4 |
| 图片 / 文件上传（MinIO） | M6 |
| 已读回执 | M5 |
| 消息互动（点赞、回复） | M5 |

### Could have（有余力再做）

| 功能 | 里程碑 |
|:---|:---:|
| 表情包、消息撤回 | M5 |
| AI 机器人接入 | M8 |
| 本地消息表 + 异步投递 | M6 |

### Won't have（明确不做）

| 不做 | 原因 |
|:---|:---|
| 电商（商品/订单/支付/购物车/物流） | MallChat 画饼未兑现，我们连饼都不画 |
| 移动端 App、离线推送（APNs/FCM） | 需外部账号，投入产出比低 |
| 多端同步、全局消息 seq 服务 | 属"IM 高可用"范畴，超纲 |
| 微服务拆分、K8s | 单机 Compose 足够 |
| 用户增长体系（邀请/积分/任务/活动） | 产品功能，非技术练习目标 |
| 管理后台 | 无业务价值 |
| 音视频通话、屏幕共享 | 完全不同的技术栈 |

> ⚠️ **想加功能先改这份文档。** 范围蔓延是练手项目的头号死因。

## 4. 用户故事与验收标准

### US-1 注册与登录
> 作为新用户，我希望能注册账号并登录。

**AC**
- [ ] 用户名全局唯一，3-20 字符，仅允许字母数字下划线
- [ ] 密码至少 8 位，含字母与数字；bcrypt 加盐哈希存储
- [ ] 登录成功返回 access_token（7 天）+ refresh_token
- [ ] 错误码：用户名已存在 / 密码错误 / 参数非法，各有独立错误码
- [ ] 登录接口频控：单 IP 10 次/分钟

**测试点**
注册成功 · 重复注册失败 · 弱密码拒绝 · 密码错误 · 登录频控触发 · token 过期刷新

### US-2 发起单聊
> 作为用户，我希望能和另一个用户一对一聊天。

**AC**
- [ ] 首次发起自动创建 `room`（type=single），重复发起复用同一 room（幂等）
- [ ] 双方会话列表都能看到该 room
- [ ] 消息按 `id` 升序，刷新不丢不乱序
- [ ] 非 room 成员读取消息 → 403

**测试点**
建 room 幂等性 · 消息顺序 · 非成员越权拦截

### US-3 实时接收消息
> 作为在线用户，我希望对方发消息时立刻收到，不用刷新。

**AC**
- [ ] WebSocket 握手需携带 token，非法 token 直接拒绝（close code 4001）
- [ ] 心跳：客户端 30s ping，服务端 60s 无响应断开
- [ ] 断线自动重连，重连带 `Last-Seq`，服务端补发缺失消息
- [ ] 同一用户多连接（多标签页）都能收到

**测试点**
握手认证 · 心跳超时 · 推送到达 · 多连接广播 · 断线补偿

### US-4 群聊
> 作为用户，我希望创建群聊并邀请多人一起聊天。

**AC**
- [ ] 建群者为群主，可踢人、可邀请
- [ ] 群成员上限 500
- [ ] 退群后不再接收该群消息，历史消息保留
- [ ] 非成员发消息/读消息 → 403

**测试点**
群消息广播 · 非成员越权 · 退群隔离 · 成员上限

### US-5 历史消息
> 作为用户，我希望向上滚动加载历史，翻页不重复不遗漏。

**AC**
- [ ] 游标分页：`WHERE id < :cursor ORDER BY id DESC LIMIT 20`
- [ ] **禁止 offset 分页**
- [ ] 返回 `next_cursor`，为 null 表示到底
- [ ] 翻页期间有新消息写入时，不重复不遗漏

**测试点**
游标边界（首页/末页）· 并发写入下的翻页稳定性

### US-6 已读回执
> 作为发送方，我希望知道对方是否已读。

**AC**
- [ ] `room_member.last_read_msg_id` 记录每个成员读到的位置
- [ ] 客户端进入会话时上报已读位点
- [ ] 会话列表显示未读数（总消息数 - 已读位置）

**测试点**
位点更新 · 未读数计算 · 并发上报

### US-7 内容安全
> 作为平台方，我希望拦截违规内容并防止接口被刷。

**AC**
- [ ] 消息发送前过敏感词，命中替换为 `***`
- [ ] 敏感词算法：DFA 为主，预留 AC 自动机接口，两者做性能对比
- [ ] 发消息频控 20 条/分钟；登录 10 次/分钟（按 IP）
- [ ] 频控命中返回 429 + 明确提示

**测试点**
敏感词替换正确 · 长文本性能 · 频控触发与恢复

## 5. 非功能需求

| 维度 | 要求 |
|:---|:---|
| 性能 | 单机支持 1000 并发 WebSocket 连接；消息端到端 P99 < 500ms |
| 可用性 | 单机部署，不要求高可用；允许重启后短暂不可用 |
| 安全 | 密码哈希、JWT 签名、越权防护、注入防护、密钥不入库 |
| 可维护性 | 分层清晰、测试覆盖、每次改表有迁移脚本 |
| 可观测 | 结构化日志 + 请求 ID 追踪 + 健康检查端点 |

## 6. 需求变更流程

```
提出需求 → 判断是否在本文档"Won't"清单 → 是则默认拒绝（除非推翻原理由）
                                      → 否则评估对里程碑的影响
                                      → 更新本文档 + BOARD.md + 记入 DECISIONS.md
                                      → 通知所有受影响角色
```

**任何需求变更必须留下"为什么"，否则三个月后没人记得当初为什么这么定。**
