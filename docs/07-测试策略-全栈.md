# 07 · 测试策略（全栈）

> 定位：测什么、怎么测、覆盖率多少算过
> 状态：v1.0
> ⚠️ **这是本项目对标 MallChat 的核心差异点，不可妥协**

---

## 0. 为什么这份文档最重要

MallChat 有 424 个 Java 文件、23,843 行代码，却只有 2 个测试类，
而且 `pom.xml` 里写死 `<skipTests>true</skipTests>`。
它自称"互联网**企业级**项目的最佳实践"——**没有测试的企业级项目不是企业级项目**。

MinIM 把测试当作一等公民：

| 指标 | 目标 | 门禁 |
|:---|:---|:---|
| 整体覆盖率 | ≥ 60% | CI 卡 |
| 核心链路覆盖率 | ≥ 80% | CI 卡 |
| 核心链路范围 | `message` / `ws` / `auth` / `room` 四个模块 | |

**覆盖率不达标，不允许合并，不允许进入下一个里程碑。**

## 1. 测试金字塔

```
        ╱╲          E2E（Playwright）        少量 · 关键链路
       ╱──╲        端到端，真实浏览器
      ╱────╲       集成测试（API + DB）       中量 · 核心
```

| 层级 | 占比 | 速度 | 测什么 |
|:---|:---:|:---:|:---|
| 单元测试 | 60% | 毫秒级 | 纯函数、模型、算法（含 DFA/AC） |

## 2. 单元测试

### 范围

| 对象 | 示例 |
|:---|:---|
| 算法 | 敏感词 DFA / AC 匹配、游标计算 |
| 校验逻辑 | 密码强度、用户名格式 |
| 模型转换 | entity ↔ DTO 的 adapter |
| 工具函数 | 时间格式化、分页参数处理 |
| 策略类 | 各消息类型的 handler |

### 规范

```python
# tests/unit/test_sensitive_filter.py
import pytest
from app.security.sensitive import DFASensitiveFilter

class TestDFASensitiveFilter:
    @pytest.fixture
    def filter(self):
        f = DFASensitiveFilter()
        f.load(["违规词", "bad"])
        return f

    @pytest.mark.parametrize("input_text,expected", [
        ("这是一段正常文本", "这是一段正常文本"),
        ("这句话有违规词在内", "这句话有***在内"),
        ("bad word", "*** word"),
        ("", ""),
    ])
    def test_filter(self, filter, input_text, expected):
        assert filter.filter(input_text) == expected

    def test_performance_large_text(self, filter, benchmark):
        text = "正常内容" * 10000
        result = benchmark(filter.filter, text)
        assert result is not None
```

**规范要点**
- 文件名 `test_*.py`，类名 `Test*`，方法 `test_*`
- 用 `parametrize` 覆盖边界，不要写 10 个几乎相同的测试
- **一个测试只验证一件事**
- 用 fixture 复用构造逻辑

## 3. 集成测试

### 环境

用 **testcontainers** 起真实的 PostgreSQL / Redis，测试完自动销毁。
**不用 SQLite 替代 PostgreSQL**——JSONB、窗口函数等行为不同，会漏 bug。

```python
# tests/conftest.py
import pytest
from testcontainers.postgres import PostgresContainer

@pytest.fixture(scope="session")
def postgres():
    with PostgresContainer("postgres:16") as pg:
        yield pg.get_connection_url()

@pytest.fixture
async def client(postgres):
    from app.main import create_app
    from httpx import AsyncClient, ASGITransport
    app = create_app(db_url=postgres)
    async with AsyncClient(transport=ASGITransport(app), base_url="http://test") as c:
        yield c
```

### 必须覆盖的场景

| 模块 | 场景 |
|:---|:---|
| auth | 注册成功 / 重复注册 / 弱密码 / 密码错误 / token 刷新 |
| room | 单聊幂等 / 建群 / 成员上限 / 退群 |
| message | 发送 / 非成员拦截 / 游标分页边界 / 撤回时限 / 点赞切换 |
| friend | 申请 / 重复申请 / 接受 / 拒绝 / 拉黑后无法申请 |
| security | 敏感词替换 / 频控触发与恢复 |

### 越权测试（重点）

```python
@pytest.mark.asyncio
async def test_non_member_cannot_read_messages(client, two_users):
    """非会话成员读取消息应返回 403"""
    alice, bob = two_users
    room = await create_room(alice)

    resp = await client.get(
        f"/api/v1/rooms/{room.id}/messages",
        headers=auth_header(bob),
    )
    assert resp.status_code == 403
    assert resp.json()["code"] == 30002
```

**每个涉及资源的接口都要有越权用例。** 这是最容易出安全漏洞的地方。

```python
@pytest.mark.asyncio
async def test_ws_auth_rejects_bad_token():
    with pytest.raises(WebSocketDisconnect) as exc:
        async with client.websocket_connect("/ws?token=invalid"):
            pass
    assert exc.value.code == 4001

@pytest.mark.asyncio
async def test_ws_receives_message(client, two_online_users):
    alice, bob = two_online_users
    async with client.websocket_connect(f"/ws?token={bob.token}") as ws:
        await send_message(alice, room_id, "hello")
        data = await asyncio.wait_for(ws.receive_json(), timeout=2)
        assert data["type"] == "message.new"
        assert data["data"]["content"] == "hello"
```

## 7. 测试命令

```bash
# 全量测试 + 覆盖率
pytest --cov=app --cov-report=term-missing --cov-report=html

# 只跑单元测试（快）
pytest tests/unit -q

# 只跑失败的（--lf = last failed）
pytest --lf

# 并行加速
pytest -n auto

# 覆盖率门禁（不达标退出码非 0）
pytest --cov=app --cov-fail-under=60
```

### pytest 配置（`pyproject.toml`）

```toml
[tool.pytest.ini_options]
asyncio_mode = "auto"
testpaths = ["tests"]
addopts = "-ra --strict-markers --cov=app --cov-report=term-missing"

[tool.coverage.run]
source = ["app"]
omit = ["*/migrations/*", "*/tests/*", "app/main.py"]

[tool.coverage.report]
exclude_lines = [
    "pragma: no cover",
    "if TYPE_CHECKING:",
    "raise NotImplementedError",
]
```

## 9. 测试数据管理

| 原则 | 说明 |
|:---|:---|
| 每个测试独立 | 用 fixture 构造数据，不依赖执行顺序 |
| 数据库隔离 | 每个测试用事务回滚，或每个用例重建 schema |
| 不用生产数据 | 测试数据全部由 factory 生成 |
| 时间可控 | 用 `freezegun` 冻结时间，测撤回时限等逻辑 |

```python
from freezegun import freeze_time

@freeze_time("2026-09-18 12:00:00")
async def test_recall_within_limit():
    msg = await create_message(age_seconds=60)
    resp = await recall(msg)
    assert resp.status_code == 200

@freeze_time("2026-09-18 12:00:00")
async def test_recall_beyond_limit():
    msg = await create_message(age_seconds=180)  # 超过 2 分钟
    resp = await recall(msg)
    assert resp.status_code == 422
```

## 10. CI 中的测试门禁

```yaml
# .github/workflows/test.yml
- name: Run tests
  run: pytest --cov=app --cov-fail-under=60

- name: Check core coverage
  run: |
    pytest --cov=app.message --cov=app.ws --cov=app.auth --cov=app.room \
           --cov-fail-under=80
```

**门禁不是收尾，是卡在流程中间的墙。**
