# MinIM · 项目总览

> 一个最小可用的即时通讯内核 · 用 Python + FastAPI 从零实现
> 项目位置：`/Volumes/SSK SSD/MinIM`
> 文档版本：v1.0 · 2026-09-18
> 状态：**S0 完成，待进 S1（编码）**

---

## 1. 一句话定位

用 Python + FastAPI 从零实现一个可运行的 IM 内核（单聊 + 群聊 + 实时推送），
借此系统练习 Python 后端工程化与分布式基础能力。

## 2. 双目标与裁决原则

| 目标 | 权重 | 说明 |
|:---|:---:|:---|
| 主目标：做出能跑的 IM | 70% | 代码能跑、功能闭环、自己用得上 |
| 副目标：验证工程化骨架 | 30% | 检验 workconfi 那套文档/流程在真实项目里是否好用 |

**冲突裁决原则：能跑 > 文档完整。**
文档跟不上代码就砍文档——不同步的文档比没文档更害人。

## 3. 成功标准（可验收）

| # | 标准 | 验收方式 |
|:--:|:---|:---|
| 1 | 两个浏览器窗口实时互发消息，延迟 < 500ms | 手动 + E2E |
| 2 | 群聊 10 人群发消息全员收到 | 集成测试 |
| 3 | 刷新后历史消息完整，翻页不卡顿不重复 | 手动 + 游标分页单测 |
| 4 | 断网重连后消息不丢 | 手动 |
| 5 | **测试覆盖率 ≥ 60%，核心链路 ≥ 80%** | `pytest --cov` |
| 6 | **`docker compose up` 一条命令启动全部依赖** | 全新目录克隆验证 |
| 7 | 敏感词、频控、越权三类安全用例有测试覆盖 | SEC 门禁 |

> 第 5、6 条刻意对标 MallChat 的短板。做不到这两条，这就只是又一个"能跑的 demo"。

## 4. 项目起源

参考 [MallChat](https://github.com/zongzibinbin/MallChat)（Java，4.6k star）。
该项目 IM 部分有真东西，但存在三处硬伤，本项目逐一回应：

| MallChat 的问题 | MinIM 的对策 |
|:---|:---|
| 宣称电商，交付 0% | **名字就叫 MinIM，非目标清单写死** |
| 424 个文件只有 2 个测试类 | 覆盖率硬指标 + 门禁 |
| 6 个外部依赖，无 compose，跑不起来 | `docker compose up` 一条命令 |

**同时继承它的 6 个好设计**（D1-D6，见 `02-系统架构.md`）。
