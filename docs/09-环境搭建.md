# 09 · 环境搭建

> 定位：从一台裸机到项目能跑起来，需要装什么、配什么、注意什么
> 状态：v1.0 · 已在 macOS (Apple Silicon) 验证

---

## ⚠️ 0. 先读：项目盘是 exFAT，这带来硬约束

项目位于 `/Volumes/SSK SSD/MinIM`，该盘为 **exFAT** 格式。

### exFAT 的特性（实测）

| 特性 | 对我们的影响 |
|:---|:---|
| ✅ 支持符号链接 | venv / node_modules 技术上可建 |
| ✅ 支持 chmod | 但**重启后不持久** |
| ❌ 无 Unix 权限位 | git 会认为所有文件 777，产生大量 mode change 噪音 |
| ❌ 无 journal | **掉盘 = 数据损坏**，不能放活跃写数据库 |
| ❌ 不支持硬链接 | pip/uv 的硬链接缓存失效，装包变慢 |
| ⚠️ 大小写不敏感 | `User.py` 与 `user.py` 会冲突 |
| ⚠️ I/O 性能与文件监听弱 | 大量小文件（node_modules）操作很慢 |

### 应对方案（本文档的核心）

```
┌─────────────────────────────────────────────────┐
│  SSD (exFAT)                                    │
│  ├─ 源码 (.py, .ts, .md)      ✅ 放这里          │
│  ├─ git 仓库                   ✅ 放这里          │
│  └─ 运行时产物                 ❌ 一律不放        │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│  本地盘 (~) / Docker Volume                      │
│  ├─ Python venv                ✅ 放这里          │
│  ├─ node_modules               ✅ 放这里          │
│  ├─ PostgreSQL / Redis 数据     ✅ Docker volume  │
│  └─ MinIO 数据                 ✅ Docker volume  │
└─────────────────────────────────────────────────┘
```

**三条铁律**

1. **源码在 SSD，运行时产物在本地盘**
2. **数据库数据只走 Docker volume，绝不落在 exFAT**
3. **不用 Docker 跑应用本身**，只用它跑依赖服务（见下）

---

## 1. 架构决策：为什么不用 Docker 跑应用

| 方案 | 问题 |
|:---|:---|
| ❌ 应用也容器化 + bind mount 源码 | exFAT 上的 bind mount 在 macOS Docker Desktop 下**极慢**，热重载几乎不可用 |
| ✅ **应用本地跑，依赖服务容器化** | 源码不需要进容器，绕开所有性能问题；启动快、调试方便 |
| ⚪ 全容器化 + 源码在容器内 | 改代码要重建镜像，开发体验差 |

**采纳方案**：

```
本地 Python (uv)  ──直连──▶  Docker 中的 PostgreSQL / Redis / MinIO
   FastAPI                        （端口映射 5432 / 6379 / 9000）
```

- 开发时：本地 `uvicorn` 跑应用，连 `localhost:5432`
- 打包时：才 build Docker 镜像（`13-部署上线.md`）

## 3. 步骤一：Git 全局配置（exFAT 必做）

```bash
cd "/Volumes/SSK SSD/MinIM"
git init

# ⚠️ exFAT 无 Unix 权限位，不关掉会产生大量无意义的 diff
git config core.fileMode false

# 关掉 macOS 的 .DS_Store 噪音
echo ".DS_Store" >> .gitignore
git config core.excludesFile .gitignore
```

**为什么必须 `core.fileMode false`**
exFAT 不存储权限位，Linux 容器/其他系统 clone 后所有文件变成 777，
git 会认为每个文件都被修改过，`git status` 一片红。

## 4. 步骤二：Docker 起依赖服务

### `docker-compose.yml`（项目根目录）

```yaml
services:
  postgres:
    image: postgres:16-alpine
    container_name: minim-postgres
    environment:
      POSTGRES_USER: minim
      POSTGRES_PASSWORD: minim_dev
      POSTGRES_DB: minim
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data   # named volume → 在本地盘
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U minim"]
      interval: 5s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7-alpine
    container_name: minim-redis
    command: redis-server --appendonly yes
    ports:
      - "6379:6379"
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10

  minio:
    image: minio/minio:latest
    container_name: minim-minio
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minim
      MINIO_ROOT_PASSWORD: minim_dev_123
    ports:
      - "9000:9000"   # API
      - "9001:9001"   # Console
    volumes:
      - miniodata:/data

volumes:
  pgdata:        # 全部是 named volume，数据在 Docker 管理的本地目录
  redisdata:
  miniodata:
```

> ✅ **关键**：全部用 **named volume**（`pgdata:`），不用 `./data:/var/lib/postgresql/data`
> 这种 bind mount。named volume 由 Docker 管理，实际存在 `~/Library/Containers`，
> **不落在 exFAT 上**，安全且性能好。

### 启动

```bash
cd "/Volumes/SSK SSD/MinIM"
docker compose up -d
docker compose ps          # 确认三个服务都 healthy
docker compose logs -f postgres   # 看日志
```

### 验证

```bash
# PostgreSQL
docker exec minim-postgres pg_isready -U minim
# 期望：/var/run/postgresql:5432 - accepting connections

# Redis
docker exec minim-redis redis-cli ping
# 期望：PONG

# MinIO
curl -s http://localhost:9000/minio/health/live && echo "OK"
# 浏览器打开 http://localhost:9001 可进控制台（minim / minim_dev_123）
```

## 5. 步骤三：Python 环境（venv 放本地盘）

### 用 uv 安装 Python 3.12

```bash
uv python install 3.12
uv python list        # 确认 3.12 已安装
```

### 创建 venv 到本地盘 ⚠️ 关键

```bash
# 不要把 .venv 建在 exFAT 上
export UV_PROJECT_ENVIRONMENT="$HOME/.venvs/minim"

cd "/Volumes/SSK SSD/MinIM"
uv venv --python 3.12
source "$HOME/.venvs/minim/bin/activate"
```

**把这一行写进 shell 配置**（`~/.zshrc`），免得每次手动设：

```bash
echo 'export UV_PROJECT_ENVIRONMENT="$HOME/.venvs/minim"' >> ~/.zshrc
```

### 安装依赖

```bash
uv pip install -r requirements.txt
uv pip install -r requirements-dev.txt
```

### 为什么要放本地盘

| 放 exFAT | 问题 |
|:---|:---|
| venv 里大量符号链接 | 创建慢，且可能因大小写不敏感出问题 |
| pip/uv 用硬链接缓存 | exFAT 不支持硬链接 → 缓存失效，每次重装全量下载 |
| 装包时大量小文件写入 | exFAT 慢 |

放本地盘（`~/.venvs/minim`）完全绕开，且**丢了能重建**，不心疼。

## 10. 常见问题排查

| 现象 | 原因 | 解决 |
|:---|:---|:---|
| `docker compose up` 报端口占用 | 本地已有 PG/Redis | `lsof -i :5432` 查并停掉，或改端口映射 |
| `git status` 一片红（所有文件 modified） | exFAT 权限位 | `git config core.fileMode false` |
| venv 创建极慢或失败 | venv 建在 exFAT | 设 `UV_PROJECT_ENVIRONMENT` 指向 `~/.venvs/minim` |
| `uv pip install` 特别慢 | exFAT 不支持硬链接，缓存失效 | 同上，venv 放本地盘 |
| 数据库连接被拒 | 容器还没 healthy | `docker compose ps` 确认 healthy 再连 |
| Alembic 找不到模型 | 未导入 model | 在 `env.py` 里 import 所有 model |
| `asyncpg` 报 SSL 错误 | 本地无需 SSL | DATABASE_URL 去掉 `?sslmode=require` |
| Docker Desktop 找不到 /Volumes | 文件共享未开启 | Docker Desktop → Settings → Resources → File Sharing 加 `/Volumes` |
| 文件监听不生效（热重载失败） | exFAT 的 inotify 支持弱 | 关掉 `--reload`，改手动重启 |
