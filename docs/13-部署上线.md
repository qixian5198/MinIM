## 0. 部署策略

| 环境 | 用途 | 部署方式 | 数据 |
|:---|:---|:---|:---|
| local | 开发 | 本地 uvicorn + Docker 依赖服务 | 测试数据 |
| staging | 预发 | Docker Compose 全栈 | 类生产数据 |
| production | 生产 | Docker Compose 全栈 | 真实数据，**需备份** |

> 本项目是练手项目，**不追求高可用**。
> 单机构署，允许重启时短暂不可用。

## 2. Dockerfile

```dockerfile
# 构建阶段
FROM python:3.12-slim AS builder

WORKDIR /build
ENV UV_PROJECT_ENVIRONMENT=/build/.venv

COPY requirements.txt .
RUN pip install --no-cache-dir uv \
    && uv venv \
    && uv pip install --no-cache -r requirements.txt

# 运行阶段
FROM python:3.12-slim

WORKDIR /app
ENV PATH="/app/.venv/bin:$PATH"
ENV PYTHONUNBUFFERED=1
ENV APP_ENV=production

# 非 root 用户（安全基线）
RUN useradd -m -u 1000 appuser

COPY --from=builder /build/.venv /app/.venv
COPY --chown=appuser:appuser app/ /app/app/
COPY --chown=appuser:appuser alembic/ /app/alembic/
COPY --chown=appuser:appuser alembic.ini /app/

USER appuser
EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2"]
```

**要点**

| 项 | 说明 |
|:---|:---|
| 多阶段构建 | 构建依赖不进运行镜像，减小体积 |
| 非 root 用户 | 容器被攻破时权限受限 |
| HEALTHCHECK | Docker 能自动判断容器是否健康 |
| `--workers 2` | 按 CPU 核数调整；**注意多 worker 会影响 WebSocket**（见下） |

> ⚠️ **WebSocket 与多 worker**
> 本项目连接注册表在进程内，多 worker 会导致消息只能推到其中一个 worker 的连接。
> **当前阶段用 `--workers 1`**，或改用 Redis 连接注册表（超出范围）。

## 3. 生产 docker-compose

```yaml
# docker-compose.prod.yml
services:
  app:
    image: minim:${TAG:-latest}
    container_name: minim-app
    env_file: .env.production
    ports:
      - "8000:8000"
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped
    command: >
      sh -c "alembic upgrade head &&
             uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1"

  postgres:
    image: postgres:16-alpine
    env_file: .env.production
    volumes:
      - pgdata:/var/lib/postgresql/data      # named volume，不在 exFAT
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER}"]
      interval: 5s
      retries: 10
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      retries: 10
    restart: unless-stopped

  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    env_file: .env.production
    volumes:
      - miniodata:/data
    restart: unless-stopped

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./deploy/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./deploy/ssl:/etc/nginx/ssl:ro
    depends_on:
      - app
    restart: unless-stopped

volumes:
  pgdata:
  redisdata:
  miniodata:
```

## 4. Nginx 配置（重点：WebSocket 升级）

```nginx
upstream minim_app {
    server app:8000;
}

server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    client_max_body_size 50m;      # 文件上传限制

    # WebSocket 必须的配置 ⭐
    location /ws {
        proxy_pass http://minim_app;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # 长连接超时（心跳 30s，这里给 300s 余量）
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    location / {
        proxy_pass http://minim_app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> ⚠️ **WebSocket 不通的 90% 原因是少了 `Upgrade` / `Connection` 这两行。**

## 5. 发布流程

```bash
# 1. 打 tag（版本号 = 日期 + 序号）
export TAG=$(date +%Y%m%d)-01

# 2. 构建镜像
docker build -t minim:${TAG} .
docker tag minim:${TAG} minim:latest

# 3. 备份数据库 ⭐ 发布前必做
docker exec minim-postgres pg_dump -U minim minim > backup-${TAG}.sql

# 4. 停旧版
docker compose -f docker-compose.prod.yml down

# 5. 起新版（compose 里会自动跑 alembic upgrade）
docker compose -f docker-compose.prod.yml up -d

# 6. 健康检查
curl -f http://localhost:8000/health || (echo "启动失败，回滚" && rollback)

# 7. 冒烟测试
./scripts/smoke-test.sh
```

### 冒烟测试脚本

```bash
#!/usr/bin/env bash
# scripts/smoke-test.sh
set -euo pipefail

BASE=${BASE:-http://localhost:8000}

echo "→ 健康检查"
curl -sf "$BASE/health" > /dev/null

echo "→ 注册测试用户"
curl -sf -X POST "$BASE/api/v1/auth/register" \
  -H 'Content-Type: application/json' \
  -d '{"username":"smoketest","password":"test1234"}' > /dev/null || true

echo "→ 登录"
TOKEN=$(curl -sf -X POST "$BASE/api/v1/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"smoketest","password":"test1234"}' | jq -r .data.access_token)

echo "→ 获取用户信息"
curl -sf "$BASE/api/v1/users/me" -H "Authorization: Bearer $TOKEN" > /dev/null

echo "✅ 冒烟测试通过"
```

## 6. 回滚方案

### 回滚策略（按优先级）

| 场景 | 回滚方式 |
|:---|:---|
| 应用代码有问题 | 切回上一个镜像 tag |
| 数据库迁移有问题 | `alembic downgrade -1` |
| 两者都有问题 | 先回滚代码，再回滚数据库 |

```bash
# 回滚应用
export PREV_TAG=20260918-01
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d   # TAG 环境变量指向旧版

# 回滚数据库（如果需要）
docker compose -f docker-compose.prod.yml exec app alembic downgrade -1

# 从备份恢复（最后手段）
docker exec -i minim-postgres psql -U minim minim < backup-20260918-01.sql
```

### 回滚检查清单

- [ ] 知道上一个版本的 tag 是什么（**发布前就要记下来**）
- [ ] 数据库备份存在且可恢复（**发布前验证过**）
- [ ] 回滚后跑冒烟测试
- [ ] 记录回滚原因

## 7. 生产配置检查

`.env.production`（**绝不提交 git**）

```bash
APP_ENV=production
DEBUG=false                        # ⚠️ 必须为 false
LOG_LEVEL=WARNING

DATABASE_URL=postgresql+asyncpg://minim:强密码@postgres:5432/minim
REDIS_URL=redis://redis:6379/0

JWT_SECRET=用 openssl rand -hex 32 生成   # ⚠️ 绝不能用开发默认值
JWT_ALGORITHM=HS256
JWT_EXPIRE_DAYS=7

MINIO_ENDPOINT=minio:9000
MINIO_ACCESS_KEY=强账号
MINIO_SECRET_KEY=强密码
MINIO_BUCKET=minim

CORS_ORIGINS=["https://your-domain.com"]
```

**生成强密钥**

```bash
openssl rand -hex 32
```

### 发布前配置自检

```bash
# DEBUG 必须关闭
grep -q "^DEBUG=false" .env.production || echo "❌ DEBUG 未关闭"

# JWT secret 不能是默认值
grep -q "change-me" .env.production && echo "❌ JWT_SECRET 仍是默认值"

# .env.production 必须在 gitignore
git check-ignore -q .env.production || echo "❌ .env.production 未被忽略"
```
