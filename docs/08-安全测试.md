# 08 · 安全测试

> 定位：系统有哪些安全面、怎么测、测到什么程度算过
> 状态：v1.0
> 执行者：SEC 角色（只报不修，由 owner 修）

---

## 0. 安全基线原则

| 原则 | 说明 |
|:---|:---|
| 默认拒绝 | 未明确授权的访问一律拒绝，而不是"没检查就放行" |
| 边界校验 | 所有外部输入在 API 层校验，不信任任何客户端数据 |
| 最小权限 | 每个接口只给完成功能所需的最小权限 |
| 密钥不入库 | 密钥、token 不写进数据库和日志 |
| 失败不泄密 | 错误信息不暴露内部细节（如 SQL、堆栈） |

## 1. 威胁模型（STRIDE 简化版）

| 威胁 | 本项目场景 | 对策 | 优先级 |
|:---|:---|:---|:---:|
| **S**poofing 假冒 | 伪造 token 访问他人数据 | JWT 签名校验 + 短期有效 | P0 |
| **T**ampering 篡改 | 篡改 room_id 读他人消息 | 服务端成员校验 | P0 |
| **R**epudiation 抵赖 | 用户否认发过消息 | 审计日志 | P2 |
| **I**nformation Disclosure 泄露 | 密码明文、日志泄露 token | bcrypt + 日志脱敏 | P0 |
| **D**enial of Service 拒绝服务 | 刷接口、刷 WebSocket 连接 | 频控 + 连接数限制 | P1 |
| **E**levation of Privilege 提权 | 普通成员执行群主操作 | 角色校验 | P0 |

## 2. 认证与会话安全

### 检查项

| # | 检查项 | 怎么测 | 通过标准 |
|:--:|:---|:---|:---|
| A1 | 密码用 bcrypt 加盐哈希 | 查数据库 `password_hash` 字段 | 非明文、非 MD5/SHA1，形如 `$2b$12$...` |
| A2 | 密码强度校验 | 提交 `12345678`、`abcdefgh` | 返回 `10004` |
| A3 | JWT 签名校验 | 篡改 payload 后请求 | 401 |
| A4 | JWT 过期校验 | 用过期 token | 401 `20002` |
| A5 | refresh token 一次性 | 重复使用同一 refresh_token | 第二次失败 |
| A6 | 无 token 访问受保护接口 | 不带 Authorization | 401 |
| A7 | token 不在 URL 中（除 WS） | 检查日志 | 无 token 泄漏 |
| A8 | 登出后 token 失效 | 加入黑名单后请求 | 401 |

### 测试用例

```python
async def test_tampered_jwt_rejected():
    token = create_token(user_id=1)
    payload = token.split(".")[1]
    tampered = tamper(payload, {"user_id": 999})   # 篡改 user_id
    resp = await client.get("/api/v1/users/me",
                            headers={"Authorization": f"Bearer {tampered}"})
    assert resp.status_code == 401

async def test_expired_jwt_rejected():
    with freeze_time("2026-01-01"):
        token = create_token(user_id=1)
    with freeze_time("2026-03-01"):   # 已过 7 天
        resp = await client.get("/api/v1/users/me",
                                headers={"Authorization": f"Bearer {token}"})
    assert resp.status_code == 401
    assert resp.json()["code"] == 20002
```

## 3. 越权测试（IDOR）⭐ 最高优先级

**水平越权**：用户 A 访问用户 B 的同类型资源
**垂直越权**：普通成员执行群主操作

### 必须覆盖的越权场景

| # | 场景 | 期望 |
|:--:|:---|:---|
| V1 | 非 room 成员读取该 room 消息 | 403 `30002` |
| V2 | 非 room 成员向该 room 发消息 | 403 `30002` |
| V3 | 非群主踢人 | 403 `30004` |
| V4 | 非消息发送者撤回消息 | 403 `40003` |
| V5 | 非申请接收方处理好友申请 | 403 |
| V6 | 被拉黑用户向对方发消息/申请 | 403 `50003` |
| V7 | 篡改 JWT 中的 user_id 访问他人会话 | 401 |
| V8 | 已退群用户读取该群历史消息 | 403 |

### 测试写法

```python
@pytest.mark.parametrize("endpoint,method,payload", [
    ("/api/v1/rooms/{room_id}/messages", "GET", None),
    ("/api/v1/messages", "POST", {"room_id": "{room_id}", "type": 1, "content": "x"}),
    ("/api/v1/rooms/{room_id}/members", "GET", None),
])
async def test_non_member_access_denied(endpoint, method, payload):
    """非成员访问任何 room 资源都应被拒绝"""
    outsider = await create_user()
    room = await create_room(owner=other_user)

    url = endpoint.format(room_id=room.id)
    if payload:
        payload = json.loads(json.dumps(payload).replace("{room_id}", str(room.id)))

    resp = await client.request(method, url,
                                headers=auth_header(outsider),
                                json=payload)
    assert resp.status_code == 403
```

> **每个涉及资源 ID 的接口都要写越权用例。**
> 这是实际项目中最常见、后果最严重的安全漏洞。

## 4. 注入防护

| 类型 | 防护 | 测试 |
|:---|:---|:---|
| SQL 注入 | 全部走 SQLAlchemy ORM / 参数化查询 | 输入 `' OR 1=1 --` 等 payload |
| NoSQL 注入 | 不适用（无 MongoDB） | — |
| XSS | React 默认转义；后端不过滤 HTML 但前端不 dangerouslySetInnerHTML | 提交 `<script>alert(1)</script>` |
| 命令注入 | 不执行系统命令 | — |
| 路径穿越 | 文件名随机化，不拼接用户输入 | 文件名 `../../etc/passwd` |

### SQL 注入测试

```python
@pytest.mark.parametrize("payload", [
    "' OR '1'='1",
    "1; DROP TABLE users; --",
    "1 UNION SELECT password_hash FROM users",
])
async def test_sql_injection_safe(payload):
    resp = await client.get(f"/api/v1/users/search?keyword={payload}",
                            headers=auth_header(user))
    assert resp.status_code in (200, 400)
    # 数据库仍然完好
    assert await count_users() > 0
```

**关键**：全部使用 ORM 的参数化查询，**禁止字符串拼接 SQL**。

```python
# ❌ 禁止
db.execute(f"SELECT * FROM users WHERE username = '{name}'")

# ✅ 正确
db.execute(select(User).where(User.username == name))
```

## 5. 频控与抗滥用

| 接口 | 维度 | 阈值 | 测试 |
|:---|:---|:---|:---|
| `/auth/login` | IP | 10/分钟 | 连打 11 次，第 11 次 429 |
| `/auth/register` | IP | 3/分钟 | 同上 |
| `POST /messages` | 用户 | 20/分钟 | 连发 21 条 |
| `POST /files` | 用户 | 10/分钟 | 连传 11 次 |
| WS 连接 | IP | 20/分钟 | 连建 21 个连接 |

### 测试

```python
async def test_message_rate_limit():
    for i in range(20):
        resp = await send_message(user, f"msg {i}")
        assert resp.status_code == 201

    resp = await send_message(user, "one too many")
    assert resp.status_code == 429
    assert "Retry-After" in resp.headers

async def test_rate_limit_recovers():
    await exhaust_limit(user)
    await redis.flush_pattern(f"rl:msg:{user.id}")   # 或等待窗口过期
    resp = await send_message(user, "ok now")
    assert resp.status_code == 201
```

**注意**：频控测试要能重置状态，否则测试间互相干扰。

## 6. WebSocket 安全

| # | 检查项 | 期望 |
|:--:|:---|:---|
| W1 | 无 token 连接 | 4001 |
| W2 | 无效 token 连接 | 4001 |
| W3 | 过期 token 连接 | 4001 |
| W4 | 单 IP 连接数超限 | 4002 |
| W5 | 心跳超时（60s 无 ping） | 服务端主动断开 4003 |
| W6 | 客户端发送格式错误 JSON | 忽略，不断开 |
| W7 | 客户端发送超大消息（>1MB） | 断开 |
| W8 | 推送不包含非该用户可见的数据 | 服务端按 room 成员过滤 |

## 7. 敏感信息保护

| # | 检查项 | 通过标准 |
|:--:|:---|:---|
| S1 | 密码不明文存储 | bcrypt |
| S2 | 日志不含密码/token | grep 日志文件无 `password`、`token` 明文 |
| S3 | 响应不含 password_hash | 检查所有用户相关响应 |
| S4 | 错误信息不含堆栈/SQL | 生产环境 `DEBUG=False` |
| S5 | JWT secret 走环境变量 | 代码中无硬编码 |
| S6 | 数据库密码走环境变量 | 同上 |
| S7 | `.env` 不进 git | `.gitignore` 包含，且 git 历史无泄露 |

### 密钥检查

```bash
# 检查代码中是否有硬编码密钥
grep -rnE "(secret|password|api_key|token)\s*=\s*['\"][A-Za-z0-9]{16,}" app/ || echo "无硬编码密钥"

# 检查 .env 是否被提交
git log --all --full-history -- .env | head -5   # 应为空
```

## 8. 文件上传安全

| # | 检查项 | 期望 |
|:--:|:---|:---|
| F1 | 文件类型白名单 | 非白名单返回 `60002` |
| F2 | 文件大小限制 | 超限返回 `60001` |
| F3 | 文件名随机化 | 存储名不含用户提供的原始名 |
| F4 | 路径穿越防护 | `../../etc/passwd` 被拒绝或随机化 |
| F5 | 不执行上传文件 | MinIO 只作存储，不经应用服务器执行 |
| F6 | 图片内容检测 | 校验 magic bytes，不只看扩展名 |

```python
async def test_filename_traversal_blocked():
    resp = await upload_file(user, filename="../../../etc/passwd", content=b"x")
    # 要么被拒，要么存储 key 被随机化
    stored = await get_stored_key(resp)
    assert ".." not in stored
```

## 10. 安全测试执行时机

```
S3 阶段（QA 之后，OPS 之前）
  ↓
SEC 角色执行本清单
  ↓
输出报告（只报不修）
  ↓
owner 修复 → 复测 → 通过才能进 OPS
```

### 门禁标准

| 级别 | 标准 |
|:---|:---|
| 🔴 阻断 | 存在 P0 项未通过（认证绕过、越权、注入、明文密码） |
| 🟠 告警 | P1 项未通过（频控缺失、连接数限制缺失） |
| 🟢 通过 | P0 全过，P1 有修复计划 |

**P0 项任一未通过，禁止进入部署阶段。**
